## B. New architecture and integration

One assistant, one conversation, one orchestrator. Every module is a backend service with **fixed tools** registered in the existing registry (`tools/module_tools.py`), so all R1 controls apply unchanged: schema validation (pydantic, extra keys forbidden), capability flag + **feature-by-role** check, identity check (tool user = turn owner), savepoint isolation, audit/tool-call logging, and `<untrusted_data>` wrapping of results. Writes reuse the R1 single-use confirmation framework (`security/tokens.py` + `api/actions.confirm`), now with a per-action capability.

```
chikku_ai/
  excel/          reader.py (safe load, profile) · writer.py (XlsxWriter) · modify.py · service.py
  analytics/      metrics.py  (11 deterministic metrics, period resolver, trace)
  imports/        studio.py   (eligibility, mapping, validation, confirmation, native Data Import, retry)
  documents/      extract.py  (PDF/DOCX/XLSX/CSV/image, pattern + AI extraction, ERP validation)
  knowledge/      index.py    (chunking, FULLTEXT index, optional embeddings, ACL-filtered search)
  voice/          service.py  (STT/TTS jobs, Redis-only audio)
  workflows/      proposals.py (validated declarative proposals, inactive creation)
  notifications/  alerts.py   (opt-in rules, dedup, cap, Notification Log)
  api/            activity.py imports.py voice.py workflows.py  (+ existing chat/actions/files/admin)
  page/chikku_activity/       Desk page "Chikku AI Activity"
  providers/      sarvam.py (new) · openai_compat/anthropic: vision parts, embeddings, STT/TTS
  services/files.py           ownership-checked attachments, private outputs
  patches/enable_r2_modules.py
```

Long-running work runs in RQ (`long` queue: turns, import validation, import execution, knowledge indexing; `short`: speech). Heavy inference (OCR/vision, speech, embeddings) is delegated to provider APIs; nothing heavy runs on the server.

## C. Excel Intelligence — **IT**

- **Generation** (`create_excel_report`): from a business metric (preferred) or from permission-checked records of a DocType (≤ `excel_max_rows`, default 20,000). Workbook: Dashboard sheet (KPI cards + chart), data sheets as Excel **tables** (filters, banded rows, **SUBTOTAL totals row**), number/date formats (Indian grouping), frozen header, conditional formatting (data bars, negatives, top-10), charts, print header/footer, and a **Source** sheet (DocTypes, filters, company, period, method, generated by/on). Stored as a private File attached to the user's conversation; download card in the chat; Job record in the Activity Centre.
- **Analysis** (`analyse_spreadsheet`, `compare_spreadsheets`): sheets, header detection, column types, blanks, distinct counts, sums/min/max/mean, IQR outliers, full-row duplicates, duplicates by chosen columns, GSTIN checksum checks, formula-cell count, sheet/file comparison by key column. States explicitly that cached values are used and formulas are not recalculated.
- **Modification** (`modify_spreadsheet`): remove duplicates, filter, sort, formula column (column refs and + − * / only), summary sheet, combine sheets, chart, format. Always a **new** file; original verified unchanged (hash test). Source formulas are kept as formulas (with their cached values). Fidelity warnings for charts, pivots, images, embedded objects, external links, connections and styles.
- **Safety:** macro workbooks rejected, ZIP-bomb guard (member count, size, compression ratio), nested archives rejected, cell limits (`excel_max_cells_read`, default 500k) with truncation flag, formula-injection-safe writing (strings always written as text).
- Live: report generated by the worker, downloaded by its owner (HTTP 200, valid XLSX), 403 without login.

## D. Conversational Import Studio — **IT**

- **Eligibility registry:** dynamic DocType metadata checks (not child/single/virtual, `allow_import`, not in Frappe's blocked list or Chikku's security denylist) **and** an administrator allow-list (Settings › Advanced Modules › Approved Import DocTypes; seeded: Customer, Supplier, Item, Item Price, Contact, Address, Lead, Sales Order, Purchase Order, Quotation, Material Request) **and** the user's own native permissions: Data Import access + **Import** permission on the target + create/write for the mode.
- **Permission investigation (as required):** this site already grants Data Import through the role **"Data Import and Export"** (9 users) via Custom DocPerm. Adding a new "Chikku AI Importer" rule would rewrite that custom permission set, so **it was not added**. Chikku import therefore requires the same rights as a native import, plus the allow-list and optional Feature Roles.
- **Mapping:** `start_import` profiles the file, suggests target DocTypes when none is given, proposes mappings (exact label/fieldname, synonyms, fuzzy match, saved templates by header signature). The panel's **mapping editor** lets the user change/ignore columns, map child-table fields (`items.item_code`, `accounts.account` …), set defaults, choose import type and a parent-key column for parent/child grouping, and save a template.
- **Validation (background job):** type conversion, Select options, mandatory fields, Link existence (permission-aware, batched), company access, duplicates within the file and against existing records (unique fields, autoname field, title field), update-mode existence, and a **dry run of ERPNext/Amba business validations**: the first N valid records (`import_dry_run_rows`, default 20) are inserted inside a savepoint and rolled back. On this site it caught a real Amba rule (Customer requires a receivable account row). Row-level errors are shown; nothing is dropped silently.
- **Preview + confirmation:** totals, valid/invalid/duplicate rows, warnings (drafts only; native per-record commits, no all-or-nothing), samples, estimated time. Token bound to user, DocType, file hash, mapping hash, selected row numbers, expiry, single use; everything re-validated at execution.
- **Execution:** native **Data Import** created and run **as the user** in an RQ job from a generated native-format CSV (fieldname / `table.field` headers). `submit_after_import` forced to 0, plus a `doc_events` guard that blocks switching it on for any Chikku-linked import. Progress via native `data_import_progress` (the panel subscribes to the Data Import room) and Chikku status events. Results: imported/failed counts, downloadable error report (XLSX), **safe retry** (new session containing only failed source rows; successful rows can never be re-sent; duplicate checks run again). History in the panel and the Activity Centre.
- Live: 3-row CSV → 2 valid / 1 invalid → confirmed → native import by the worker → exactly 2 Customers, Data Import owned by the user with `submit_after_import = 0`; token replay rejected.

## E. Document Intelligence — **IT** (pattern + validation) · **AC** (AI/vision extraction)

- Text extraction: PDF (pdfplumber text + tables), scanned PDFs rendered with pypdfium2 for vision, DOCX (zip + hardened lxml, macro documents rejected), XLSX/CSV, images (Pillow verify + normalise). Multiple attachments are referenced by file ID.
- Extraction without AI: GSTIN (checksum-validated), document/PO numbers, dates, taxable, CGST/SGST/IGST, grand total, each with evidence text.
- AI extraction (vision slot → fallback to main model): strict JSON schema with per-field confidence and evidence; merged with pattern results; conflicts noted; low-confidence fields flagged; injection-looking text flagged. **Never invents values** (scanned image without a vision model returns no fields and says so).
- ERP validation: supplier by GSTIN / name, open Purchase Orders and **unbilled Purchase Receipts** of the supplier, in-state/out-state GST template suggestion, item matching, arithmetic checks, duplicate supplier bill number.
- **Draft Purchase Invoice** (`prepare_purchase_invoice_draft`): confirmation-gated, backdate rule, cost centre, tax template, duplicate bill check, mandatory-field check in memory. Built with **ERPNext's own Purchase Receipt → Purchase Invoice mapping**, because this site's Buying Settings require **both a Purchase Order and a Purchase Receipt** (found during testing). The PO/PR due date and payment schedule are recalculated. Creates a Draft that enters the "Verify Purchase Invoice" workflow; never submits.

## F. Business Intelligence — **IT**

11 deterministic metrics, all through `frappe.get_list` (role permissions, User Permissions including Company/Warehouse, sharing): `sales_summary` (by none/month/customer/item/item group/territory/customer group/sales person), `purchase_summary`, `period_comparison` (month by month, % change), `receivables` / `payables` (ageing buckets), `stock_balance` (valuation by warehouse/item), `slow_moving` (no outward movement for N days), `stock_shortages` (negative projected + below reorder level), `delayed_sales_orders`, `delayed_purchase_orders`, `manufacturing` (status, completion %, delays, material consumption).

- Period resolver (today … last_N_months, fiscal years via ERPNext, custom); company scope follows ERPNext semantics (User Permissions on Company); every result carries a **trace** (source DocTypes, filters, company, period, method, sample records).
- UI: KPI cards, bar/line/pie charts, tables, "How this was calculated", document cards. Follow-up questions reuse the previous analysis parameters stored on the conversation. Excel export via `create_excel_report`.
- Accuracy test: sales total and invoice count equal an independent SQL sum; grouped totals reconcile; receivables total reconciles.

## G. Company Knowledge — **IT** (FULLTEXT) · **AC** (embedding re-rank)

- **Chikku AI Knowledge Document** (Desk form): PDF/DOCX/TXT/MD/CSV/XLSX, category, visibility *Only Me / Selected Roles / All Chikku AI Users*. Saving queues indexing (worker): text extraction, heading/page-aware chunks, optional embeddings (Embedding slot), status/error shown.
- Retrieval: the permission filter runs **first** (`get_list` with visibility rules), then MariaDB **FULLTEXT** over only those documents, with a LIKE fallback and optional cosine re-rank. No vector database was added: MariaDB 10.11 has no vector type, and FULLTEXT + re-rank fits this corpus and server.
- Answers must cite `[n]`; no sources means "no supporting document was found". Citations link to the source document.
- Live: worker indexed a document; the chat answer carried its citation via real FULLTEXT search. Tests: owner-only, role-based and no-Chikku-access isolation.

## H. Voice — **AC** (functional; no real speech provider configured)

- Push-to-talk mic (only rendered when a Speech Recognition provider is configured), first-use **privacy notice/consent** (stored with timestamp), max recording length, cancel, editable transcript in the composer, automatic language detection of the transcript, **read aloud** per message (when Speech Synthesis is configured) with stop, and **interruption** (starting to speak stops playback).
- Providers: **Sarvam** (STT `speech-to-text`, TTS `text-to-speech`; contract verified against docs.sarvam.ai) and OpenAI-compatible (`audio/transcriptions`, `audio/speech`). Provider-independent through model slots.
- Privacy: audio lives only in Redis (≤ 120 s) and is deleted when transcription runs; synthesized speech goes straight to the browser and is never stored.
- Live: consent enforced; audio sent by the worker to a Sarvam-protocol server; transcript delivered over socket.io and detected as Hinglish.

## I. Workflow Intelligence — **IT**

## J. Proactive Notifications — **IT**

- Opt-in per user (`subscribe_alert` at the user's request, or the Alert Subscription list): Overdue Sales Orders, Delayed Purchase Deliveries, Low Stock, Pending Approvals (native Workflow Actions), Failed Imports. Frequency Day/Hour, company, threshold days.
- Hourly scheduler evaluates each subscription **as its owner**. Duplicates are suppressed (same result signature → no new alert), with a daily cap per user. Each alert stores its records and source trace and raises a native **Notification Log** (bell) plus a realtime badge. Acknowledge/dismiss API; other users can't see or change it.

## K. AI Activity Centre — **IT**

Desk page **/desk/chikku-activity**: conversations, reports/Excel jobs, imports, knowledge documents, draft actions, workflow proposals and alerts, with type, status and date filters and pagination. Safe retries only: import (failed rows, re-validated), knowledge re-index, failed report regeneration. Administrators can pick a user and see operational metadata only (conversation titles, file names and summaries hidden); there's also a usage overview (requests, tokens, cost, models, jobs, imports, security events). Linked from the chat header, which shows a new-alert badge.

## M. Security and permissions

All R1 controls unchanged and re-tested. Added:
- File ownership for every input; outputs are private Files attached to the owner's records (owner download 200, anonymous 403, other user denied).
- Import: native Import permission + Data Import access + admin allow-list + Feature Roles; token binding to file/mapping hashes and rows; `submit_after_import` guard; execution as the user (no permission bypass).
- Documents/knowledge content always wrapped as untrusted; injection phrases flagged.
- Knowledge ACL enforced before retrieval; "has_permission" hooks only narrow access (a dedicated read rule plus a hook implements visibility).
- Workflow changes admin-only, token-confirmed, created inactive; condition language restricted by AST.
- Alerts evaluated as their owner; Activity Centre shows administrators metadata only.
- **Bug fixed during live testing:** a tool whose result counted rows as an integer was treated as failed after finishing, which rolled back its file while its download card stayed. Row counting is now robust, and any cards or tokens added by a failed tool are discarded (regression tests added).

## S. Known limitations

- Real vendor validation pending (O).
- No browser on the server, so the UI was verified by SSR rendering tests and HTTP, not visually. Please try the panel and the Activity page in a browser.
- Native import commits per record, so there's no all-or-nothing import (stated in the UI). The dry run covers the first 20 records only.
- Purchase Invoice drafts require a Purchase Receipt (site rule). Draft actions remain **off** until an administrator enables them.
- Anomaly detection is limited to IQR outliers in spreadsheets; there's no ML forecasting.
- Knowledge indexing has no OCR for scanned documents yet (it reports this).
- **Site emails:** three native **Auto Email Reports** are enabled on this test site (PO Tracking → divya@simpel.ai; PO Status Summery → divya@simpel.ai; PO Fulfilment & Tracking → several Amba staff and finance addresses). They are separate from the scheduled job stopped earlier and still send daily. They were not changed (team-owned configuration); disable them if the test site must not email anyone.
- `hooks.py` mixes R2 Chikku hooks with the uncommitted barcode hooks again. Committing R2 needs the same partial staging as R1.
